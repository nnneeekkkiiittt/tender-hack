# Tender operational support — сводка проекта

Сервис поддержки по тендерной документации: пользователь пишет вопрос,
на него отвечает локальная ИИ-модель с цитированием источников, а при
необходимости обращение эскалируется живым операторам поддержки трёх
уровней (L1 → L2 → L3). Всё — единый чат, без потери контекста при передаче.

## Что реализовано

- **Аккаунты и роли**: `user`, `admin`, `supportL1/L2/L3`. Регистрация,
  логин, смена/сброс пароля, HttpOnly cookie-сессии с отзывом при смене
  пароля.
- **Обращения (claims)**: создание, список, поиск, фильтрация по
  статусу/категории/оператору; жизненный цикл `NEW → IN WORK → DONE`
  (или `CANCELLED` автором).
- **Единый чат AI → L1 → L2 → L3**: первый вопрос сразу получает ответ от
  ИИ; дизлайк ответа или любое следующее сообщение передают диалог в L1;
  классификатор может направить обращение сразу в L1/L2/L3, минуя ИИ;
  дальше эскалирует только назначенный оператор, последовательно, без
  пропуска уровней.
- **ИИ-модуль** (`ml_service`): маршрутизация intent → мультизапросный
  ретривер по базе из 6 руководств (830 страниц, 1276 чанков) → генерация
  ответа с цитатами → карточка контекста для оператора. Локально —
  CPU-профиль (E5 + Qwen3 через llama.cpp + Qdrant), без внешних API и без
  GPU-зависимости, чтобы демо воспроизводилось одной командой на любой
  машине.
- **Модерация** (`moderation_service`): каждое сообщение пользователя
  проверяется до записи в базу; заблокированный текст нигде не
  сохраняется и не уходит в ИИ, черновик остаётся редактируемым.
- **Оценки**: отдельный отклик на ответ ИИ (триггерит эскалацию при
  дизлайке) и оценка финального оператора после `DONE` (не триггерит).
- **Аналитика** (`analytics`, Go): поднимается отдельным Compose-профилем,
  не подключена к текущему фронтенду — вынесена в отдельный сервис
  намеренно (см. `FEATURE_SPEC.md`).

Полный перечень принятых решений, сценариев приёмки и границ ответственности
между сервисами — в [`FEATURE_SPEC.md`](FEATURE_SPEC.md).

## Архитектура

```
frontend (React) ── backend (FastAPI + PostgreSQL/Liquibase)
                        │
                        ├──▶ moderation_service (RuBERT + правила)  — проверка текста до записи
                        └──▶ ml_service (Qwen3 + E5 + Qdrant)        — ответ + маршрутизация
```

Backend — единственный сервис, который пишет в операционную БД; ML и
модерация — стейтлес-сервисы без доступа к PostgreSQL. Подробное обоснование
такого разделения — в [`DECISIONS.md`](DECISIONS.md), разделы 2–3.

## Быстрый запуск (демо)

```sh
git clone <this-repository-url> tender-hack
cd tender-hack
./scripts/demo-up.sh
```

Открыть **http://localhost:8080**, переключаться между ролями через
**Демо → Admin / L1 / L2 / L3 / Consumer**. Первый запуск: ~8 ГБ RAM,
~10 ГБ диска, несколько минут на скачивание моделей. Без загрузки
ИИ-модели: `./scripts/demo-up.sh --mock` (модерация всё равно скачивает
свою модель — 48 МБ).

Полная инструкция по установке, переменным окружения и разработке — в
[`README.md`](README.md).

## Тесты

```sh
bash db/tests/run.sh
bash backend/tests/run.sh
cd frontend && npm run lint && npm run build && npx playwright install chromium && npm run test:e2e
cd ../ml_service && uv run pytest -q
cd ../moderation_service && uv run pytest -q
```

Реально пройдено на момент интеграции ИИ: 35 backend-тестов, unit/contract
тесты ML-пайплайна, 6 браузерных регрессий на изолированной mock-БД и один
opt-in прогон на реальной модели (полный сценарий вопрос → ответ →
дизлайк → L1 → эскалация до L2/L3). Подробности и точные цифры по
времени ответа — в [`ML_INTEGRATION_REPORT.md`](ML_INTEGRATION_REPORT.md).

## Известные ограничения (не скрываем, а фиксируем как следующие шаги)

- Генерация ответа ИИ синхронная и держит открытой транзакцию создания
  заявки — на демо-нагрузке это не проблема, для продакшена нужна очередь.
- Порог схожести ретривера и предпочтение "версионных" изданий —
  эвристики прототипа, не откалиброванная метрика точности.
- Модерация не распознаёт часть составных ругательств моделью — они
  закрыты словарными правилами.
- Демо-переключатель ролей (`DEMO_ACCOUNTS=true`) даёт мгновенный
  админ-доступ без пароля — только для локальной демонстрации, не для
  публичного или боевого деплоя.

Полное и аргументированное объяснение, почему сделано именно так, а не
иначе — по каждому из ключевых решений — см. [`DECISIONS.md`](DECISIONS.md).
